# 07 · 异步任务与定时调度设计（Celery）

> 本设计基于现有 CMS 业务，用 Celery 落地「异步任务 + 定时调度」能力。

## 0. Celery 核心概念

| 概念 | 作用 |
| --- | --- |
| Task | 一个后台任务（`@celery_app.task` 装饰的函数） |
| Worker | 消费执行任务的进程（`celery worker`） |
| Broker | 任务消息队列（本项目用 Redis） |
| Beat | 定时调度器（`celery beat`），按 crontab 周期投递任务 |
| Result Backend | 任务结果存储（本项目用 Redis） |
| `delay` / `apply_async` | 入队执行 / 带参数入队 |
| `eta` / `countdown` | 指定时间 / 延迟执行 |
| `retry` | 失败重试 + 指数退避 |

**核心思想**：把耗时/非关键路径的操作从请求主链路剥离，丢进队列异步执行；把周期性动作交给 Beat 调度器。

## 1. Celery 应用与任务组织

```python
# app/tasks/celery_app.py
from celery import Celery
from celery.schedules import crontab
from app.core.config import settings

celery_app = Celery(
    "cms",
    broker=settings.CELERY_BROKER_URL,       # redis://localhost:6379/0
    backend=settings.CELERY_RESULT_BACKEND,  # redis://localhost:6379/1
)

celery_app.conf.update(
    task_serializer="json",
    result_serializer="json",
    accept_content=["json"],
    timezone="Asia/Shanghai",
    enable_utc=False,
    # 按业务域划分队列
    task_routes={
        "app.tasks.notification.*": {"queue": "notification"},
        "app.tasks.media.*": {"queue": "media"},
        "app.tasks.batch.*": {"queue": "batch"},
        "app.tasks.schedule.*": {"queue": "schedule"},
    },
    # 定时调度
    beat_schedule={
        "daily-snapshot": {
            "task": "app.tasks.schedule.daily_snapshot",
            "schedule": crontab(hour=0, minute=30),
        },
        "review-timeout-remind": {
            "task": "app.tasks.schedule.review_timeout_remind",
            "schedule": crontab(minute=0),  # 每小时
        },
        "publish-sweep": {
            "task": "app.tasks.schedule.publish_sweep",
            "schedule": crontab(minute="*/5"),  # 每 5 分钟
        },
    },
)

# 自动发现任务模块
celery_app.autodiscover_tasks(["app.tasks"])
```

### ⚠️ Celery 任务与 asyncio 的配合

Celery 任务默认是**同步**执行。若任务里要访问 async SQLAlchemy，二选一：

```python
# 方案一：任务内用 asyncio.run 包装（简单直接）
import asyncio

@celery_app.task
def publish_content(content_id: str):
    asyncio.run(_async_publish(content_id))

async def _async_publish(content_id: str):
    async with async_session() as db:
        ...
```

```python
# 方案二：为 Celery 单独配同步 engine（更规范，推荐）
# app/db/session.py 中同时提供 sync_engine / SessionLocal
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

sync_engine = create_engine(settings.SYNC_DATABASE_URL)
SessionLocal = sessionmaker(bind=sync_engine)

@celery_app.task
def publish_content(content_id: str):
    with SessionLocal() as db:
        ...
```

> 推荐方案二：Celery 用同步 SQLAlchemy，FastAPI 用 async SQLAlchemy，各司其职。

## 2. 异步任务清单

### 2.1 通知任务（notification）

- **触发时机**：审核通过/驳回后、定时发布成功后
- **重试策略**：3 次，指数退避（5s → 10s → 20s）
- **幂等**：以 `{event}:{contentId}` 做任务唯一标识

```python
# app/tasks/notification.py
from .celery_app import celery_app

@celery_app.task(bind=True, max_retries=3, default_retry_delay=5)
def notify(self, event: str, content_id: str, author_id: str):
    try:
        send_notification(event=event, content_id=content_id, author_id=author_id)
    except Exception as exc:
        # 指数退避：5s → 10s → 20s
        raise self.retry(exc=exc, countdown=5 * (2 ** self.request.retries))

# 业务代码只入队，不阻塞响应
# notify.delay(event="approved", content_id=content_id, author_id=author_id)
```

### 2.2 媒体处理任务（media）

- **触发时机**：图片上传成功后
- **内容**：生成缩略图、压缩原图、提取宽高

### 2.3 发布后处理任务

- **触发时机**：内容发布成功后
- **内容**：预热缓存、生成静态 HTML 快照
- **要点**：发布本身同步完成，预热/快照才异步

### 2.4 批量操作任务（batch，带进度）

- **触发时机**：用户勾选多条内容点「批量发布」
- **内容**：逐条处理，进度写入 Redis，前端轮询进度条
- **要点**：最有学习价值的**长任务进度反馈**模式

```python
# app/tasks/batch.py
from .celery_app import celery_app
import redis as sync_redis

redis_client = sync_redis.from_url(settings.REDIS_URL)

@celery_app.task(bind=True)
def batch_publish(self, ids: list[str]):
    total = len(ids)
    for i, cid in enumerate(ids):
        publish_one(cid)
        redis_client.set(f"batch:{self.request.id}:progress", f"{i + 1}/{total}")
    redis_client.set(f"batch:{self.request.id}:progress", "done")
```

### 2.5 报表导出任务（export）

- **触发时机**：用户点「导出」按钮
- **内容**：异步生成 CSV/Excel，完成后通知下载

### 2.6 定时发布（延迟任务）

```python
# 延迟到 scheduledAt 执行
publish_content.apply_async(args=[content_id], eta=scheduled_at)
```

## 3. 定时调度清单（celery beat）

| 任务 | crontab | 内容 | 为什么需要 |
| --- | --- | --- | --- |
| daily-snapshot | `crontab(hour=0, minute=30)` | 生成昨日统计快照 | 工作台趋势图数据来源 |
| review-timeout-remind | `crontab(minute=0)` | 扫描超 24h 未审核内容，提醒审核员 | 审核不积压 |
| publish-sweep | `crontab(minute="*/5")` | 扫描到期未发布内容，触发发布 | 防延迟任务丢失的兜底 |
| cleanup-expired | `crontab(hour=3, minute=0)` | 清理过期 token、超期软删除内容 | 数据库瘦身 |
| warm-cache | `crontab(hour=6, minute=0)` | 预热热门内容缓存 | 早高峰首屏更快 |

```python
# app/tasks/schedule.py
from .celery_app import celery_app

@celery_app.task
def daily_snapshot():
    yesterday = ...
    stats = compute_stats(yesterday)
    save_snapshot(stats)

@celery_app.task
def publish_sweep():
    # 兜底：扫描 scheduled_at <= now 且 approved 的内容
    for c in find_due_contents():
```

## 4. 可靠性与幂等（重点学习）

1. **幂等**：任务要能被重复执行而不产生副作用（如通知用 `{event}:{contentId}` 去重）。
2. **重试**：只对「可重试的失败」`self.retry()`（如网络抖动）；业务校验失败应直接抛错不重试。
3. **兜底扫描**：定时发布既用延迟任务，又用 beat 兜底扫描，双保险。
4. **断点续跑**：批量任务记录进度，崩溃后能从中断处继续。
5. **监控**：监控队列积压长度（如用 Flower 可视化），积压即告警。

## 5. 学习路径建议

1. 先跑通最简单的异步任务（「发布后发通知」），理解「`delay` 入队 → worker 消费」链路。
2. 再加定时调度（「每日统计快照」），理解 `crontab` 与 `beat_schedule`。
3. 最后做「批量发布带进度条」，掌握长任务进度反馈 + 幂等 + 断点续跑。

> 掌握这套后，异步任务与定时调度的通用方法论即建立，任何语言/框架都能迁移。
