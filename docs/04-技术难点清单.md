## 1. JWT 认证 + Refresh Token 轮换

**问题**：access token 泄漏后如何止损？如何无感续期？

**解法**：access token 短时效（15 分钟），refresh token 长时效（7 天），refresh 时轮换并吊销旧 token。

**要点**：
```python
# app/core/security.py
from jose import jwt
from passlib.context import CryptContext
from datetime import datetime, timedelta

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def create_access_token(user_id: str) -> str:
    expire = datetime.utcnow() + timedelta(minutes=15)
    return jwt.encode({"sub": user_id, "exp": expire}, settings.SECRET_KEY, algorithm="HS256")

def hash_password(p: str) -> str:
    return pwd_context.hash(p)

def verify_password(p: str, h: str) -> bool:
    return pwd_context.verify(p, h)
```

```python
# app/api/v1/auth.py —— refresh 轮换
@router.post("/refresh")
async def refresh(payload: RefreshRequest, db: AsyncSession = Depends(get_db)):
    stored = await db.scalar(
        select(RefreshToken).where(
            RefreshToken.token_hash == hash(payload.refreshToken),
            RefreshToken.revoked_at.is_(None),
            RefreshToken.expires_at > datetime.utcnow(),
        )
    )
    if not stored:
        raise HTTPException(401, "refresh token 无效")
    async with db.begin():
        stored.revoked_at = datetime.utcnow()
        new_tokens = issue_tokens(stored.user_id)
    return new_tokens
```

**踩坑**：refresh token 必须落库才能主动吊销；并发刷新会双发，用唯一约束或乐观锁防重。

## 2. RBAC 权限模型（菜单级 + 接口级）

**问题**：如何统一控制「能进哪个页面」和「能调哪个接口」？

**解法**：用户 → 角色 → 权限码。接口级用**依赖注入**实现守卫。

**要点**：
```python
# app/core/deps.py
def require_permission(code: str):
    async def checker(user: User = Depends(get_current_user)):
        if "*" not in user.permissions and code not in user.permissions:
            raise HTTPException(status_code=403, detail="无权限")
        return user
    return checker

# 使用：路由级依赖
@router.get("/contents", dependencies=[Depends(require_permission("content:read"))])
async def list_contents(...): ...
```

**踩坑**：权限码收敛到一处常量定义，前后端共享；依赖注入要在 `get_current_user` 之后。

## 3. 多租户隔离（数据层根治越权）

**问题**：跨租户越权是后台最危险的 bug，靠业务层 `where` 容易漏。

**解法**：从请求头 `X-Tenant-Id` 取租户上下文，查询统一强制过滤。

**要点**：
```python
# app/core/deps.py
from fastapi import Header

async def get_current_tenant(x_tenant_id: str = Header(None)) -> str:
    if not x_tenant_id:
        raise HTTPException(400, "缺少租户上下文")
    return x_tenant_id

# service 层统一过滤
async def list_contents(db: AsyncSession, tenant_id: str, **filters):
    stmt = select(Content).where(
        Content.tenant_id == tenant_id,
        Content.deleted_at.is_(None),
    )
    return (await db.scalars(stmt)).all()
```

**进阶**：用 SQLAlchemy 2.0 的 `with_loader_criteria` 或自定义 `AsyncSession` 工厂，自动为所有查询注入租户过滤。

**踩坑**：`update/delete` 必须同时带 `tenant_id` 条件，否则会改到别的租户。

## 4. 多语言 i18n 数据建模

**问题**：同一内容多语言，字段怎么存？

**方案对比**：
| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 翻译表（本项目） | 独立加载、独立版本、索引友好 | 多一次 join |
| JSONB 单字段 | 查询简单 | 难索引、难局部更新 |

**要点**：`ContentTranslation` 表，`content_id + locale` 唯一，缺失语言回退默认语言。

**踩坑**：slug 在语言维度也要唯一；语言列表要可配置。

## 5. 版本管理（历史快照 + diff + 回滚）

**问题**：如何保留每次提交，支持对比与回滚？

**解法**：`ContentVersion` 存完整快照；回滚 = 读快照写回 + `version + 1`。

**要点**：
```python
async def rollback(db: AsyncSession, content_id: str, version_id: str):
    snap = await db.get(ContentVersion, version_id)
    async with db.begin():
        content = await db.get(Content, content_id)
        content.body = snap.body
        content.title = snap.title
        content.version += 1
        db.add(ContentVersion(content_id=content_id, version=content.version,
                              body=snap.body, title=snap.title, change_note="回滚"))
```

**踩坑**：版本号是乐观锁；快照存完整 HTML，不要存引用。

## 6. 审核状态机 + 乐观锁

**问题**：并发审核如何防止状态错乱？

**解法**：显式状态迁移表 + 乐观锁（`version` 字段）。

**要点**：
```python
TRANSITIONS = {
    "draft": ["pending"],
    "pending": ["approved", "rejected"],
    "rejected": ["draft"],
    "approved": ["published"],
    "published": ["archived"],
}

async def transition(db: AsyncSession, content_id: str, from_: str, to: str):
    if to not in TRANSITIONS.get(from_, []):
        raise HTTPException(409, "非法状态流转")
    res = await db.execute(
        update(Content)
        .where(Content.id == content_id, Content.status == from_, Content.version == current_version)
        .values(status=to, version=Content.version + 1)
    )
    if res.rowcount == 0:
        raise HTTPException(409, "内容已被修改，请刷新")
```

**踩坑**：非法流转显式拒绝；用 `rowcount` 判断乐观锁是否命中。

## 7. 定时发布（Celery 延迟任务 + 分布式锁）

**问题**：定时发布如何多实例下只触发一次？

**解法**：Celery `apply_async(eta=...)` 延迟任务，消费端用 Redis 分布式锁防重。

**要点**：
```python
# tasks/publish.py
from celery import Celery
celery_app = Celery("cms", broker="redis://localhost:6379/0")

@celery_app.task(bind=True, max_retries=3)
def publish_content(self, content_id: str):
    lock_key = f"lock:publish:{content_id}"
    if not redis.set(lock_key, "1", ex=30, nx=True):
        return  # 已被其他 worker 处理
    try:
        # 发布逻辑（用同步 sqlalchemy 或独立事件循环）
        do_publish(content_id)
    finally:
        redis.delete(lock_key)

# 入队（延迟到 scheduledAt）
publish_content.apply_async(args=[content_id], eta=scheduled_at)
```

**踩坑**：任务幂等（`task_id` 唯一）；锁要有超时防死锁；取消定时要 `revoke`。

## 8. 缓存策略（穿透 / 击穿 / 雪崩 / 一致性）

**问题**：热点内容详情如何缓存，且不与数据库打架？

**解法**：Cache-Aside + 单飞锁 + 过期抖动。

**要点**（redis.asyncio）：
```python
import redis.asyncio as aioredis
redis = aioredis.from_url(settings.REDIS_URL, decode_responses=True)

async def get_content_cached(db, content_id: str):
    cached = await redis.get(f"content:{content_id}")
    if cached:
        return json.loads(cached)
    locked = await redis.set(f"lock:content:{content_id}", "1", ex=5, nx=True)
    if not locked:
        return await get_content_cached(db, content_id)  # 单飞等待
    data = await db.get(Content, content_id)
    await redis.set(f"content:{content_id}", json.dumps(data), ex=60 + random.randint(0, 30))
    await redis.delete(f"lock:content:{content_id}")
    return data
```

**踩坑**：不要缓存含敏感字段的对象；缓存 key 带租户维度。

## 9. 分页与复杂查询（游标 vs 偏移、索引、N+1）

**问题**：大表 OFFSET 深翻页慢；列表查询 N+1。

**解法**：浅分页用 offset，深分页用游标；`selectinload` 一次性加载关联。

**要点**：
```python
from sqlalchemy.orm import selectinload

# 防 N+1：selectinload 批量加载关联
stmt = (
    select(Content)
    .options(selectinload(Content.translations), selectinload(Content.tags))
    .where(Content.tenant_id == tenant_id)
    .order_by(Content.id.asc())
    .limit(page_size)
    .offset((page - 1) * page_size)
)
```

**踩坑**：按需 `selectinload`，过多关联会拖慢查询；组合索引列顺序匹配查询条件。

## 10. 事务与并发（隔离级别、死锁）

**问题**：跨多表写如何保证原子性？并发下死锁？

**解法**：SQLAlchemy `async with db.begin()` 事务块；按固定顺序加锁避免死锁。

**要点**：
```python
async with db.begin():
    content = await db.get(Content, content_id)
    content.status = "published"
    review = await db.get(Review, review_id)
    review.status = "approved"
    db.add(OperationLog(...))  # 审计
```

**踩坑**：事务内不做耗时 IO（发邮件、调第三方）；事务范围尽量小；捕获 `IntegrityError` 处理冲突。

## 11. 软删除与审计日志

**问题**：删除后要能追溯，关键操作要留痕。

**解法**：`deleted_at` 软删除，查询默认过滤；`OperationLog` 表记录操作。

**要点**：查询统一 `where(deleted_at.is_(None))`；写操作后异步落日志（用 Celery，不阻塞响应）。

**踩坑**：日志用异步任务落库；敏感字段（密码）脱敏后记录。

## 12. 文件上传（大小限制、路径安全）

**问题**：如何安全接收文件，防路径穿越与类型伪造？

**解法**：`UploadFile` 流式接收，限制大小与类型，服务端重命名。

**要点**：
```python
from fastapi import UploadFile, File
import uuid

@router.post("/upload")
async def upload(file: UploadFile = File(...), tenant_id: str = Depends(get_current_tenant)):
    content = await file.read()
    if len(content) > 20 * 1024 * 1024:
        raise HTTPException(413, "文件过大")
    if not file.content_type.startswith(("image/", "video/", "application/pdf")):
        raise HTTPException(415, "不支持的文件类型")
    ext = Path(file.filename).suffix
    safe_name = f"{uuid.uuid4().hex}{ext}"
    (UPLOAD_DIR / safe_name).write_bytes(content)
    ...
```

**踩坑**：不要信任 `file.filename` 拼路径；返回 URL 要经过鉴权。

## 13. 数据库迁移（Alembic）

**问题**：数据库结构演进如何版本化、如何安全应用？

**解法**：Alembic（SQLAlchemy 官方迁移工具）。

**要点**：
```bash
alembic init alembic                 # 初始化
alembic revision --autogenerate -m "init"   # 自动生成迁移
alembic upgrade head                 # 应用迁移
alembic downgrade -1                 # 回滚一个版本
```

**踩坑**：迁移文件提交到 git；生产禁用 `autogenerate`；破坏性变更（删列）分两步。

## 14. 结构化日志 + traceId 请求追踪

**问题**：线上问题如何快速定位某次请求的完整链路？

**解法**：中间件生成 `traceId`（`contextvars` 传递），结构化日志贯穿。

**要点**：
```python
# app/main.py
import uuid
from contextvars import ContextVar

trace_id_var: ContextVar[str] = ContextVar("trace_id", default="-")

@app.middleware("http")
async def trace_middleware(request: Request, call_next):
    trace_id = request.headers.get("x-request-id") or uuid.uuid4().hex
    trace_id_var.set(trace_id)
    response = await call_next(request)
    response.headers["x-request-id"] = trace_id
    return response
```

**踩坑**：`traceId` 透传到 Celery 任务（任务里也要带）；日志要可聚合检索。
